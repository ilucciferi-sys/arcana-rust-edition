# Этапы и критерии готовности

## 1. Аудит — начат

- [x] Отдельная копия Horizon и исходная ревизия upstream.
- [x] Инвентаризация Java/JSON/PNG/OGG и SHA-256 исходников и ресурсов.
- [x] Начальный разбор каста, прогрессии, маны, ритуалов, пакетов и огненной высшей магии.
- [x] Исследование серверного потока, CustomPayload, существующих частиц, HDR,
  динамического освещения и native post hooks Horizon.
- [ ] Полный семантический разбор всех механик и тестов, не только инвентаризация.
- [x] [Удалённый GitHub-форк](https://github.com/ilucciferi-sys/arcana-rust-edition).

Arcana использует NeoForge 1.21.1/Java 21, Horizon — 26.3/Rust/wgpu 30.
Java-классы, Mixins, NeoForge attachments, Player Animator и BendyLib требуют
замены. Каталог и авторские текстуры/звуки можно сохранить; форматы моделей,
скин-слои, импорт анимаций и проигрывание звука требуют адаптеров.

В Horizon уже есть CPU vanilla particles, динамическое скалярное освещение
на 16 ближайших источников, HDR output, GPU culling, LOD и post-processing hooks.
Цветной свет от заклинаний, GPU-симуляция магических частиц и VFX timeline
не должны подменять или дублировать vanilla-системы.

## 2. Архитектура — первый срез

- [x] Независимый от рендера Rust-каталог всех 76 определений с исходными ID и параметрами.
- [x] Базовая прогрессия, мана, cooldown, JSON state, одноразовые resurrection entitlements.
- [x] Авторитетный каст, отмена с возвратом маны до выпуска и сохранением cooldown.
- [x] Серверный start tick, versioned events, bounded deduplication, разделение client intent/server facts.
- [x] Модуль GPU VFX без зависимости от игровой логики Arcana.
- [ ] Полный перенос MagicData, журнала полёта и Java NBT migration.
- [ ] Реестр исполнителей остальных механик, inventory/items, UI и ритуалы.
- [x] Атомарное сохранение магического прогресса адаптером Horizon по миру/UUID,
  резервная версия и возврат маны незавершённой подготовки.
- [x] Русский HUD, выбор реализованных заклинаний, Rust-запускатель с четырьмя тестовыми профилями.
- [x] Четыре ритуала стихий: оригинальные конструкции и условия, приседание,
  серверное пробуждение первого уровня, прогресс, визуальные события и очистка.
- [ ] Ритуал Некромантии с предметом души, первым слугой и анимацией.

## 3. Прототип — Солнечное копьё

Источник: FireSpells.solarSpear и ReworkSpells.blast. Не менять 128 маны,
70 тиков подготовки, 1400 тиков КД, дальность 32, мощность 48, радиус 12.
Первое столкновение ограничивает конец луча; один взрыв, без двойного линейного
урона; промах не взрывается. Падение урона ограничено минимумом 10%.

- [x] Реализация геометрии и урона через CombatWorld, тесты ключевых случаев.
- [x] Экспериментальные серверный/клиентский адаптеры и opt-in renderer hook.
- [x] GPU shader validation, три бюджета частиц, HDR emission, bloom.
- [x] Проверка feature arcana в полной сборке Horizon.
- [x] Нативный запуск и первоначальная визуальная проверка подготовки, выпуска, удара и затухания.
- [x] Базовая проверка попадания в стену и в железного голема; здоровье мишени снижается.
- [x] Два клиента на localhost: эффект виден наблюдателю, один серверный выпуск на каст.
- [ ] Полная проверка коллизий, PvP, сетевых задержек, late join и очистки состояний.

Прототип пока работает с мобами: PvP ещё не подключён. Изменение территории
отключено до реализации breakSoft/permissions, заморозка и её защита от импульса
ожидают собственного игрового адаптера. Это технические границы среза, не решение
упростить итоговые механики. Ладонь приблизительная до переноса скелетной анимации.
Отображается одна композиция одновременно; планировщик нескольких эффектов ещё нужен.

## 4. Демонстрация — технический прототип

Сняты реальные кадры из Horizon на RTX 5070/Vulkan, профиль High, 1280×720.
Первоначальную чрезмерную плотность частиц уменьшили после визуального просмотра.
Эффект также снят со второго клиента. Короткий прогон не заменяет профилирование,
проверку всех профилей и дальнейшую художественную проработку.
Подробности: [отчёт проверки](VALIDATION.md).

## 5. Массовый перенос — начат со стартовых способностей

Реализованы игровые прототипы `spark`, `water_bolt`, `stone_bolt`, `wind_gust`:
фиксированные серверные тики, непрерывные проверки столкновений снарядов,
разные скорости и физика, урон/статусы/импульсы, сектор и видимость порыва,
опыт за успешное попадание, отдельные визуальные композиции.
Добавлены `ignition` и `fire_push`: выбор цели до стены, сферический сектор,
проверка видимости каждой цели, сохранение более долгого горения, прямой импульс,
однократная награда за каст и разные визуальные композиции.
Для полной приёмки ещё нужны PvP, интеграция холода, разрешённый огонь по блокам,
анимации и звук. Наличие прототипа не означает завершённый перенос способности.

Далее остальные семейства Огня,
Воды, Земли, все 15 индивидуальных механик Воздуха и 16 Некромантии. Для каждой:
механика, коллизии, статусы, анимации, уникальный VFX, звук, networking и cleanup.
Отдельно: временные блоки и восстановление мира, слуги/голем/лошадь, формы,
прогрессия, ритуалы, HUD/колесо, команды, предметы и совместимость сохранений.

## 6. Оптимизация — не начата

Измерить CPU/GPU, lifetime/LOD/frustum culling композиций, fill-rate прозрачности,
материалы, pooling и многопользовательские сцены. Бюджеты 4K/16K/49K частиц
являются параметрами прототипа и должны быть обоснованы замерами.
У стартовых снарядов есть простые геометрические следы. Distortion/refraction,
цветное освещение мира, полноценная система trails, decals, volumetrics,
screen-space effects и cinematic camera ещё не реализованы.

## 7. Приёмка — не начата

Одиночная игра на server thread; dedicated server; два и более клиента;
late join, повторная доставка, потеря связи, смерть/respawn, измерения,
восстановление прогресса и временной территории после перезапуска; все 76 механик.
Java GameTest должны превратиться в самостоятельные Rust/host differential fixtures.
